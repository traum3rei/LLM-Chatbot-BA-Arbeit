\chapter{Entwicklung}
\label{c:dev}
Nach dem Abschluss der Konzeption kann zur Entwicklung über gegangen werden.
Die Rahmenbedingungen hierbei sind, dass der Hetzner Server, welcher in 
\ref*{s:konz:ser} beschrieben wurde verwendet wird und auf diesem Ubuntu
22 installiert ist.

\section{Vorbereitung}
Bevor mit der Entwicklung begonnen werden kann, müssen ein paar 
Vorbereitungen getroffen werden.

\subsection{Modelle}
\label{s:konz:mod}
Der erste Schritt ist es die Modelle vorzubereiten.\par
Um die Modelle vorbereiten zu können, wird als erstes 
Ollama installiert.
Dies kann über das Install Skript, welches auf Github zu finden \cite{OllamaOllama2024}
ist getan werden. Dazu werden noch die Nvidia Cuda Driver installiert, 
damit Ollama diese nutzen kann. Nun können die Modelle vorbereitet werden.\par
\iffalse Hierfür werden die Modelle, die in \ref{s:konz:mod} vorgestellt
wurden über Huggingface gedownloadet.
Dies ist relativ simple über Git LFS zu erledigen.
Die Repositories der Modelle werden einfach über git clone kopiert.
Wenn die Dateien fertig gedownloadet sind, kann man die Modelle 
für das Importieren in Ollama vorbereiten.
Hierfür \par Nachdem Ragas nicht mit den von Huggingface in Ollama geladenen

Hierfür werden die Modelle, die in \ref*{s:konz:mod} vorgestellt 
wurden über Ollama gedownloadet.
Die Modelle werden über \verb|Ollama pull model| geladen, wobei \verb|model| der Name
des Models ist, welches man herunterladen möchte. Hierbei kann

mit der Google Chat API.\par
Der erste Schritt hierbei ist es, ein Google Cloud Projekt zu erstellen.

Für die Entwicklung wird innerhalb dieser Arbeit erst Pseudo-Code 
gegeben und im Text wird dann die genaue Entwicklung mit den 
benutzten Frameworks beschrieben.

Für den Importer wird der Langchain \verb|ConfluenceLoader|
verwendet. Hierfür wird, nachdem der Docker Container, welcher 
die ChromaDB Datenbank beinhaltet gestartet wurde, eine Verbindung 
zu diesem hergestellt. Dabei wird dem Chroma Client innerhalb 
des Python Programms der \verb|host| und der \verb|port| des
Docker Containers übergeben.\par
Danach wird das Embedding Modell mittels der \verb|HuggingFaceEmbeddings|
von langchain geladen. Hier wird der Name des Modells, "intfloat/multilingual-e5-large-instruct" übergeben.
Dazu gibt es die Option Keyword Arguments mittels \verb|encode_kwargs| und \verb|model_kwargs| mitzugeben.
Hier geben wir das \verb|device_kwargs| \verb|device| mit dem Wert \verb|cuda| mit. 
Dies sorgt dafür, dass die GPU für die Berechnungen verwendet wird, was den Prozess 
beschleunigt.\par
Nun können die Daten aus Confluence mittels \verb|ConfluenceLoader| geladen werden.
Hier werden \verb|username|, \verb|api_key| und die \verb|url| der Confluence Instanz 
benötigt. Nach dem Erstellen des Loaders können die Daten geladen werden, hierfür gibt
es die \verb|load| Funktion, welche einen \verb|space_key| braucht, für 
den Confluence Space der geladen werden soll.\par
Die geladenen Dokumente, werden mittels \verb|MarkdownHeaderTextSplitter| ein mal 
aufgeteilt und mittels \verb|RecursiveCharacterTextSplitter| noch ein weiteres 
mal aufgeteilt. Den aufgeteilten Dokumenten werden die Metadaten hinzugefügt, damit 
sie zugeordnet werden können.\par
Anschließend wird eine Langchain Chroma Instanz erstellt, die auf den vorher bereits
erstellten Client zugreift, dann werden die Dateien mittels \verb|from_documents| 
innerhalb einer Chroma Collection, die man beim Erstellen über die Chroma Instanz 
mittels \verb|collection_name| festlegen kann, gespeichert.

Die Entwicklung des Chatbots wird in die einzelnen Teile der Langchain Chain aufgeteilt, 
die in \ref*{chain} dargestellt ist.
Die Chain besteht aus verschiedenen Element, die bereits zu Chains zusammengefügt wurden.
Das Prompt und die LLM wurden mittels \verb|create_stuff_documents_chain| miteinander 
verbunden. Diese Chain wurde dann mittels \verb|create_retrieval_chain| mit einem Retriever 
verbunden. Als letztes wurde diese Chain in eine \verb|RunnableWithMessageHistory| 
eingebaut. Im Folgenden werden die einzelnen Teile erklärt.

\subsubsection{Retriever}
\iffalse
\begin{algorithm}
    \caption{Retriever Initialisierung}
    \begin{algorithmic}[1]
    \STATE \textbf{Class} Retriever:
    \STATE \textbf{Method} \_\_init\_\_(model\_name, model\_kwargs, encode\_kwargs, client\_settings):
    \STATE \quad Initialisiere Vektorddatenbank Client
    \STATE \quad Initialisiere Embeddings 
    \STATE \quad Erstelle Vektordatenbank Instanz mit Embeddings und Client
    \STATE \quad Erstelle Retriever mit Vektordatenbank Instanz
    \STATE \quad Rückgabe: Retriever 
    \end{algorithmic}
    \end{algorithm}
    \fi
Der erste Teil der Chain der entwickelt wird, ist der \verb|Retriever|. 
Der Retriever ist der Teil der Chain, der auf die Vektordatenbank zugreift und 
die passenden Dokumente von dieser an die LLM übergibt.\par
Hierfür wird, wie beim Importer in \ref*{s:ent:imp} ein Chroma Client erstellt, der 
mit dem Docker Container der Chroma Instanz verbunden wird, dazu wird ebenfalls 
synchron zum Importer, das Embedding Modell über \verb|HuggingFaceEmbeddings| geladen
und in der Chroma Instanz als \verb|embedding_function| angegeben.
Dieser wird dann mit der Funktion \verb|as_retriever()| als Retriever geladen.\par
Für die Chain wird dazu noch eine Funktion erstellt, welche die Dokumente, die der 
Retriever abruft zusammenfügt, damit diese der LLM übergeben werden können.

\subsubsection{Prompt}
\iffalse
\begin{algorithm}
    \caption{Initialisierung des Chatbot Prompts}
    \begin{algorithmic}[1]
    \STATE \textbf{Class} ChatbotPrompt:
    \STATE \textbf{Method} \_\_init\_\_():
    \STATE \quad Definiere Prompvorlage mit Systemnachrichten und Platzhaltern für Benutzereingaben
    \end{algorithmic}
    \end{algorithm}

Das Prompt wird mittels \verb|ChatPromptTemplate.from_messages| erstellt.
Das Prompt, welches benutzt wird, ist Folgendes: \par
    Dein Name ist Arthur. Du bist ein erfahrenes Mitglied 
    des IT-Support-Teams der Firma TechDivision. Deine Aufgabe ist es, Mitarbeitern 
    bei ihren IT-Problemen zu helfen. Beachte folgende Richtlinien: 
    \begin{enumerate}
        \item Nutze ausschließlich die Informationen aus dem bereitgestellten Kontext und deinem vorhandenen Wissen über allgemeine IT-Konzepte, um Fragen zu beantworten. 
        \item Wenn die Antwort nicht im Kontext oder in deinem allgemeinen IT-Wissen enthalten ist, sage ehrlich, dass du die Information nicht hast oder die Frage nicht beantworten kannst.
        \item Erfinde oder halluziniere keine Informationen. 
        \item Beziehe dich auf frühere Teile der Konversation, wenn sie relevant sind. 
        \item Bleibe stets höflich, professionell und hilfsbereit. 
        \item Wenn nötig, frage nach weiteren Details, um das Problem besser zu verstehen. 
        \item Gib schrittweise Anleitungen, wenn du eine Lösung vorschlägst. 
        \item Verweise den Mitarbeiter an andere Abteilungen oder Experten, wenn das Problem außerhalb deines Zuständigkeitsbereichs liegt. 
        \item Antworte auf Deutsch.
    \end{enumerate}
    Kontext: \{\verb|context|\} 
    Bisheriger Chatverlauf: \{\verb|chat_history|\} 
    Beantworte die folgende Frage des Mitarbeiters basierend auf diesen Informationen. \par
Wobei context, über über die Chain übergebene RAG Dokumente sind und chat\_history ebenfalls über
die Chain übergebene Chat Historie ist. Die Richtlinien, sollen der LLM eine Richtung geben 
und dazu falsche Informationen und Halluzinationen vermeiden.

\subsubsection{Nachrichten Historie}
\iffalse
\begin{algorithm}
    \caption{Session Manager}
    \begin{algorithmic}[1]

    \STATE \textbf{Method} get\_session\_history(session\_id):
    \STATE \quad Rückgabe einer Session mit Session Id 
    \end{algorithmic}

Die Nachrichten Historie wird mittels \verb|RunnableWithMessageHistory| 
implementiert. Hierfür wurde noch eine \verb|get_session_history| Funktion implementiert, 
welche aus einer SQLite Datenbank mittels der \verb|session_id| den aktuellen Session 
Chat abruft. Dem \verb|RunnableWithMessageHistory| muss ein Runnable Objekt 
übergeben werden, welches als Basis dient. Hier ist das Basis Runnable Objekt, 
die Retrieval Chain, die aus dem Prompt, dem Retriever und der LLM besteht.
Dazu wird der Runnable die \verb|get_session_history| Funktion übergeben.
Da das Basis Runnable ein dict als Input benötigt, muss ein \verb|input_messages_key|
angegeben werden, was laut dem Prompt, welches verwendet wird der Key \verb|input| ist. 
Dazu wird der \verb|output_messages_key| \verb|answer| übergeben und der \verb|history_messages_key|
\verb|chat_history|. \par\par

Dieses \verb|RunnableWithMessageHistory| Runnable kann mit \verb|runnable.invoke()| angesprochen werden.
Der Funktion werden zwei dict Objekte mitgegeben. 
Das dict mit dem \verb|input| Key, der die Eingabe des 
Nutzers ist und dazu noch ein weiteres dict mit einem 
\verb|configurable| Key, dessen Wert ein dict ist, 
mit einem \verb|session_id| key.

     im jeweiligen Thread geantwortet wird und sonst wird außerhalb des Threads geantwortet.

\subsection{Nachrichtenverarbeitung}
\iffalse
\begin{algorithm}
    \caption{POST Endpoint}
    \begin{algorithmic}[1]
    \STATE Definiere POST-Endpunkt "/":
    \STATE \quad Empfange und parse JSON-Anfrage
    \STATE \quad Extrahiere Nachrichtentext, Benutzerinformationen, Thread-Name und E-Mail-Host
    \STATE \quad Überprüfe, ob der E-Mail-Host gültig ist
    \STATE \quad \quad Wenn nicht gültig:
    \STATE \quad \quad \quad Rückgabe einer Fehlermeldung
    \STATE \quad Generiere Sitzungs-ID basierend auf dem Thread
    
    \STATE \quad Initialisiere Retriever mit angegebenen Einstellungen
    \STATE \quad Initialisiere ChatbotPrompt zur Abrufung der Promptvorlage
    
    \STATE \quad \quad Initialisiere LLMManager mit Modell
    
    \STATE \quad Erstelle eine Kette mit LLMManager und Retriever
    \STATE \quad Initialisiere Kette mit SessionManager 
    \STATE \quad Führe Kette aus, um Antwort auf Benutzereingabe zu erhalten
    
    \STATE \quad Initialisiere GoogleChatClient mit Anmeldedaten
    \STATE \quad Verwende GoogleChatClient, um Antwortnachricht in Google Chat mit Benutzername und Antwort zu senden
    
    \STATE \quad Rückgabe einer Antwort, die anzeigt, dass die Nachricht gesendet wurde
    \end{algorithmic}
    \end{algorithm}
    \fi
Für die Verbindung an die Google Cloud API wird ein 
POST Endpunkt erstellt. Dieser Endpunkt nimmt die Nachrichten, 
die in Google Chat an den Chatbot gesendet werden an.
Die JSON Nachricht, die man von der API erhält beinhaltet 
viele Informationen. Für den Chatbot sind die ID des Nutzers, 
der die Nachricht abschickt, der Thread in dem die Nachricht 
versendet wurde und die Nachricht, die abgesendet wurde, wichtig.
Dazu wird noch die Email überprüft, die die Nachricht abgeschickt hat.\par
Zuerst wird überprüft, ob der Email Host ein valider Email Host ist, der 
Zugang auf diesen Bot haben sollte. \par
Die ID des Nutzers, die unter \verb|message.sender.name| zu finden ist,
wird benutzt um den Nutzer in der Nachricht anzusprechen. Die 
Nachricht, die abgesendet wird beginngt hierfür mit @message.sender.name
und dadurch kann über die API ein Nutzer angesprochen werden. Wenn man 
den \verb|message.sender.displayName| verwendet, dann wird der Nutzer 
nicht in der Nachricht verlinkt, sondern es ist nur ein Text, der 
im Google Chat ankommt. \par
Der Thread ist unter \verb|message.thread.name| zu finden. Die Thread 
ID, welche der letzte Teil der Nachricht ist, wird verwendet um die 
Session ID herzustellen und sie wird als \verb|thread.name| an die API
geschickt.\par
Ein GoogleChatClient wird initialisiert und die notwendigen Infos 
werden an diesen übergeben und die Nachricht wird abgesendet.

\subsection{Server Konfiguration}
Damit die Google Chat API den Server akzeptiert, wird ein SSL Zertifikat 
benötigt. In diesem Fall wurde Nginx verwendet um das SSL Zertifikat 
zu laden und als Reverse-Proxy für den FastAPI Server. 
Der FastAPI Server wird als Service gestartet und für die Demo 
wurden 4 Unicorn Worker, für den FastAPI Server benutzt.
