\chapter{Entwicklung}
\label{c:dev}
Nach dem Abschluss der Konzeption kann zur Entwicklung über gegangen werden.
Die Rahmenbedingungen hierbei sind, dass der Hetzner Server, welcher in 
\ref*{s:konz:ser} beschrieben wurde verwendet wird und auf diesem Ubuntu
22 installiert ist.

\section{Vorbereitung}
Bevor mit der Entwicklung begonnen werden kann, müssen ein paar 
Vorbereitungen getroffen werden.

\subsection{Modelle}
\label{s:ent:mod}
Der erste Schritt ist es die Modelle vorzubereiten.\par
Um die Modelle vorbereiten zu können, wird als erstes 
Ollama installiert.
Dies kann über das Install Skript, welches auf Github zu finden \cite{OllamaOllama2024}
ist getan werden. Dazu werden noch die Nvidia Cuda Driver installiert, 
damit Ollama diese nutzen kann. Nun können die Modelle vorbereitet werden.\par

Hierfür werden die Modelle, die in \ref*{s:konz:mod} vorgestellt 
wurden über Ollama gedownloadet.
Die Modelle werden über \verb|Ollama pull model| geladen, wobei \verb|model| der Name
des Modells ist, welches heruntergeladen werden soll. Hierbei kann
mittels \verb|model:latest| noch die Version, die benötigt wird, angeben werden, wobei \verb|latest|, die Version des Modells ist. 
Darüber kann ebenfalls die Größe oder spezielle Version des Modells 
angefragt werden. Die verschiedenen Modelle haben verschiedene 
Optionen. Auf Ollama.com
können die jeweiligen Modelle und die verschiedenen Versionen, eingesehen werden.

\subsection{Google Cloud}
Hier geht es um die Vorbereitung des Google Cloud Projekts für die Verbindung 
mit der Google Chat API.\par
Der erste Schritt hierbei ist es, ein Google Cloud Projekt zu erstellen.
Wenn dies erledigt ist, muss die Google Chat API innerhalb des 
Projekts aktiviert werden.\par
Dazu wird ein Google Service Account benötigt, der auf die Google Chat API zugreifen kann.
Die Konfiguration der API wird stattfinden, nachdem der Server konfiguriert wurde 
und das System funktionsfähig ist.

\subsection{Datenbank}
Hierfür wird auf dem Server Docker installiert.
Dazu wird \verb|chromadb/chroma| über \verb|docker pull| 
heruntergeladen und dann mittels \verb|docker run| gestartet.

Algorithm \ref*{main} zeigt den generellen Ablauf des Importers.
Für den Importer wird der Langchain \verb|ConfluenceLoader|
verwendet. Dieser wird über die DocumentLoader Klasse in Algorithm \ref*{DocumentLoader} gesetzt. 
Hierfür wird, nachdem der Docker Container, welcher 
die ChromaDB Datenbank beinhaltet gestartet wurde, eine Verbindung 
zu diesem hergestellt. Dabei wird dem Chroma Client innerhalb 
des Python Programms der \verb|host| und der \verb|port| des
Docker Containers in Algorithm \ref*{VectorDB} übergeben.\par
Danach wird das Embedding Modell in Algorithm \ref*{embedding} mittels der \verb|HuggingFaceEmbeddings|
von langchain geladen. Hier wird der Name des Modells, \verb|intfloat/multilingual-e5-large-instruct|, übergeben.
Dazu gibt es die Option Keyword Arguments mittels \verb|encode_kwargs| und \verb|model_kwargs| mitzugeben.
Hier wird das \verb|device_kwargs| \verb|device| mit dem Wert \verb|cuda| gesetzt. 
Dies sorgt dafür, dass die GPU für die Berechnungen verwendet wird, was den Prozess 
beschleunigt.\par
Nun können die Daten aus Confluence mittels \verb|ConfluenceLoader| geladen werden.
Hier werden \verb|username|, \verb|api_key| und die \verb|url| der Confluence Instanz 
benötigt. Nach dem Erstellen des Loaders können die Daten geladen werden, hierfür wird 
die \verb|load| Funktion, welche einen \verb|space_key| braucht, für 
den Confluence Space der geladen werden soll, verwendet.\par
Die geladenen Dokumente, werden wie in Algorithm \ref*{splitter} dargestellt über Splitter aufgeteilt.
Hierfür werden die Dokumente mittels \verb|MarkdownHeaderTextSplitter| ein mal 
aufgeteilt und mittels \verb|RecursiveCharacterTextSplitter| noch ein weiteres 
mal aufgeteilt. Den aufgeteilten Dokumenten werden die Metadaten hinzugefügt, damit 
sie zugeordnet werden können.\par
Anschließend wird eine Langchain Chroma Instanz erstellt, die auf den vorher bereits
erstellten Client zugreift, dann werden die Dateien mittels \verb|from_documents| 
innerhalb einer Chroma Collection, die beim Erstellen über die Chroma Instanz 
mittels \verb|collection_name| festgelegt wird, gespeichert.

Der erste Teil der Chain der entwickelt wird, ist der \verb|Retriever|. 
Der Retriever ist der Teil der Chain, der auf die Vektordatenbank zugreift und 
die passenden Dokumente von dieser an die LLM übergibt.\par
Der Retriever wird über den RetrieverManager in Algorithm \ref{retriever} konfiguriert.
Hierfür wird, wie beim Importer in \ref*{s:ent:imp} ein Chroma Client erstellt, der 
mit dem Docker Container der Chroma Instanz verbunden wird, dazu wird ebenfalls,
wie beim Importer, das Embedding Modell über \verb|HuggingFaceEmbeddings| geladen
und in der Chroma Instanz als \verb|embedding_function| angegeben.
Dieser wird dann mit der Funktion \verb|as_retriever()| als Retriever geladen.
Das wichtige hierbei ist es den selben \verb|collection_name| wie beim Importer 
anzugeben.\par

\subsubsection{Prompt}
\begin{algorithm}
    \caption{Initialisierung des Chatbot Prompts}
    \begin{algorithmic}[1]

    \STATE \textbf{Method} \_\_init\_\_():

Das Prompt wird über Algorithm \ref{prompt} mittels \verb|ChatPromptTemplate.from_messages| erstellt.
Das Prompt, welches benutzt wird, ist Folgendes: \par
    Dein Name ist Arthur. Du bist ein erfahrenes Mitglied 
    des IT-Support-Teams der Firma TechDivision. Deine Aufgabe ist es, Mitarbeitern 
    bei ihren IT-Problemen zu helfen. Beachte folgende Richtlinien: 
    \begin{enumerate}
        \item Nutze ausschließlich die Informationen aus dem bereitgestellten Kontext und deinem vorhandenen Wissen über allgemeine IT-Konzepte, um Fragen zu beantworten. 
        \item Wenn die Antwort nicht im Kontext oder in deinem allgemeinen IT-Wissen enthalten ist, sage ehrlich, dass du die Information nicht hast oder die Frage nicht beantworten kannst.
        \item Erfinde oder halluziniere keine Informationen. 
        \item Beziehe dich auf frühere Teile der Konversation, wenn sie relevant sind. 
        \item Bleibe stets höflich, professionell und hilfsbereit. 
        \item Wenn nötig, frage nach weiteren Details, um das Problem besser zu verstehen. 
        \item Gib schrittweise Anleitungen, wenn du eine Lösung vorschlägst. 
        \item Verweise den Mitarbeiter an andere Abteilungen oder Experten, wenn das Problem außerhalb deines Zuständigkeitsbereichs liegt. 
        \item Antworte auf Deutsch.
    \end{enumerate}
    Kontext: \{\verb|context|\} 
    Bisheriger Chatverlauf: \{\verb|chat_history|\} 
    Beantworte die folgende Frage des Mitarbeiters basierend auf diesen Informationen. \par
Wobei context, die über die Chain übergebenen RAG Dokumente sind und chat\_history die über
die Chain übergebene Chat Historie ist. Die Richtlinien, sollen der LLM eine Richtung geben 
und dazu falsche Informationen und Halluzinationen vermeiden.

In Algorithm \ref*{gcloud} ist der Pseudo Code für den Google Chat Client dargestellt.

\subsubsection{Nachrichtenverarbeitung}
Für die Verbindung an die Google Cloud API wird ein 
POST Endpunkt erstellt. Der Pseudo Code des POST Endpunkts 
ist in Algorithm \ref*{post} dargestellt. Dieser Endpunkt nimmt die Nachrichten, 
die in Google Chat an den Chatbot gesendet werden an.
Die JSON Nachricht, die von der API abgeschickt wird beinhaltet 
viele Informationen. Für den Chatbot sind die ID des Nutzers, 
der die Nachricht abschickt, der Thread in dem die Nachricht 
versendet wurde und die Nachricht, die abgesendet wurde, wichtig.
Dazu wird noch die Email überprüft, die die Nachricht abgeschickt hat.
In \ref*{msg_get} ist das Format der Nachricht, welche der Chatbot 
erhält, dargestellt.\par
Zuerst wird überprüft, ob der Email Host ein Email Host ist, der 
Zugang auf diesen Bot haben sollte. \par
Der Thread ist unter \verb|message.thread.name| zu finden. Die Thread 
ID, welche der letzte Teil der Nachricht ist, wird verwendet um die 
Session ID herzustellen und sie wird in der Antwort als \verb|thread.name| an die API
geschickt.\par

\subsubsection{Chatbot Chain}
Nachdem die Session ID erstellt wurde, werden aus dem Modell des LLMManagers und dem 
Prompt des ChatbotPrompts mit der Funktion \verb|create_stuff_document_chain()| eine Stuff 
Document Chain erstellt. Mit dieser und dem Retriever aus dem RetrieverManager wird über die Funktion \verb|create_retrieval_chain()|
eine Retrieval Chain erstellt und daraus wird final die Runnable with Message History erstellt.\par

Der \verb|RunnableWithMessageHistory| muss ein Runnable Objekt 
 welches als Basis dient, übergeben werden. Hier ist das Basis Runnable Objekt, 
die Retrieval Chain.
Dazu wird der Runnable die \verb|get_session_history| Funktion aus Algorithm \ref{sessio} übergeben.
Da das Basis Runnable ein dict als Input benötigt, muss ein \verb|input_messages_key|
angegeben werden, was laut dem Prompt, welches verwendet wird der Key \verb|input| ist. 
Dazu wird der \verb|output_messages_key| \verb|answer| übergeben und der \verb|history_messages_key|
\verb|chat_history|. \par\par

Dieses \verb|RunnableWithMessageHistory| Runnable kann mit \verb|runnable.invoke()| gestartet werden.
Der Funktion werden zwei dict Objekte mitgegeben. 
Das dict mit dem \verb|input| Key, der die Eingabe des 
Nutzers ist und dazu noch ein weiteres dict mit einem 
\verb|configurable| Key, dessen Wert ein dict ist, 
mit einem \verb|session_id| key und der jeweiligen \verb|session_id|. \par

\subsubsection{Absenden der Nachricht}
Die ID des Nutzers, die unter \verb|message.sender.name| zu finden ist,
wird benutzt um den Nutzer in der Nachricht anzusprechen. Die 
Nachricht, die abgesendet wird beginnt hierfür mit \verb|<message.sender.name>|
und dadurch kann über die API ein Nutzer angesprochen werden. Dies funktioniert nur
über die ID. Wenn stattdessen
der DisplayName aus \verb|message.sender.displayName| verwendet wird, dann wird der Nutzer 
nicht in der Nachricht verlinkt. \par
Das finale JSON Objekt ist in \ref*{msg_send} dargestellt.\par
Ein GoogleChatClient wird initialisiert und die notwendigen Infos 
werden an diesen übergeben und die Nachricht wird abgesendet.
Das wichtige hierbei ist, dass, wenn eine asynchrone Nachricht abgeschickt wird, 
am Ende eine leere Antwort als Rückgabewert angegeben wird. Wenn diese leere Antwort nicht
zurück gegeben wird, 
kann es aktuell passieren, dass die API eine Inaktivität des Bots meldet 
und die asynchrone Nachricht erst danach ankommt. 

\subsection{Server Konfiguration}
Damit die Google Chat API den Server akzeptiert, wird ein SSL Zertifikat 
benötigt. Das SSL Zertifikat wurde über certbot generiert und es wurde Nginx verwendet um das SSL Zertifikat 
zu laden und als Reverse-Proxy für den FastAPI Server zu nutzen. 
Der FastAPI Server wird als Service gestartet und für die Demo 
wurden 4 Unicorn Worker, für den FastAPI Server benutzt. 

\subsection{Google Chat API Konfiguration}
Nachdem der Chatbot fertig gestellt wurde und der Server
ein SSL Zertifikat und eine URL besitzt, kann die Google Chat 
API Konfiguration fertig gestellt werden.\par
Der API muss ein Anwendungsname gegeben werden. Über diesen 
kann die API im Chat angesprochen werden. Dazu wird eine URL zu 
einem Bild benötigt, welches das Profilbild im Chat sein wird 
und eine Beschreibung des Projekts.\par
Die interaktiven Features müssen aktiviert sein und 
die Option Gruppenbereichen und Unterhaltungen beitreten
muss ausgewählt sein.\par
Als Verbindungseinstellung wird Anwendungs-URL ausgewählt und 
es wird die URL zum Server eingetragen.\par
Da dies nur ein Prototyp ist, wird dieser noch nicht auf 
dem Google Workspace Marketplace veröffentlicht. Da Nutzer 
die App bewerten werden brauchen diese Zugriff, diese können 
im Abschnitt \verb|Sichtbarkeit| manuell eingetragen werden. 
Damit ist die Entwicklung des Chatbots und die Konfiguration der API 
abgeschlossen.

\subsection{Chatbotinteraktion}
Der Chatbot kann nun über Google Chat wie jeder 
andere Teilnehmer des Workspaces angeschrieben werden.
Wenn der Chatbot einem Space hinzugefügt werden soll, dann 
muss dieser als App hinzugefügt werden und nicht als Nutzer.\par
In \ref*{chat} ist eine Chatinteraktion mit dem Bot dargestellt.
Auf der linken Seite ist der generelle Space sichtbar und auf der 
rechten Seite ein Thread.\par
In \ref*{thread} ist eine Interaktion dargestellt in der die 
Erinnerungen des Bots angefragt werden und es ist 
erkennbar, dass der Bot sich an die vorherige Frage erinnern kann.
